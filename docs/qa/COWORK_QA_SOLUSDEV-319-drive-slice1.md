# COWORK QA — SOLUSDEV-319 drive slice 1: the `solus-input` helper on real hardware

## What this covers

Slice 1 of ADR-041 ("SOL drives desktop tools"): the `solus-input` helper and the companion's `drive`
server. Nothing is wired into the app yet — SOL cannot drive anything. This pass checks, on a real Mac,
the behaviours unit tests cannot: the window server, Accessibility, ScreenCaptureKit, the HID idle
counter and real mouse/keyboard posting. Spec: `docs/architecture/sol-drive.md` §2–3.

**This pass moves the mouse and types in KiCad.** Use a throw-away KiCad project. Keep your hand off the
mouse and keyboard while a command runs unless a step tells you otherwise.

## Setup

1. macOS 14+, KiCad 9/10 at `/Applications/KiCad`, a scratch project open in the Schematic Editor with
   some empty canvas.
2. Build the helper:

   ```bash
   cd apps/desktop/native/solus-input && swift build -c release
   ```

3. `H=apps/desktop/native/solus-input/.build/release/solus-input` (from the repo root).
4. Grant **Accessibility** and **Screen Recording** to the terminal app you run these commands from
   (System Settings › Privacy & Security). Remove both grants when you finish — in the shipped design
   only the signed helper app holds them (sol-drive.md §1).
5. Every command prints one JSON line. To run a command against KiCad, make KiCad frontmost:
   `sleep 3; $H …` then click the KiCad window within 3 s.

## Edge cases

- Two displays: identify/capture/act on KiCad on the secondary display (coordinates still window-relative). [ ]
- Retina vs non-Retina display: capture proportions still match (flow 3). [ ]
- Terminal WITHOUT Accessibility: any `act` → `not_trusted`, nothing posted. [ ]
- Terminal WITHOUT Screen Recording: `capture` → `screen_recording_denied`. [ ]
